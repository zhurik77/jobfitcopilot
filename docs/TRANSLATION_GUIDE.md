# Руководство по переводу (i18n Contribution Guide)

Спасибо за интерес к переводу Job Fit Copilot! Этот гайд описывает, как добавить новый язык в расширение.

---

## Текущее состояние переводов

| Язык | Статус | Файл |
|------|--------|------|
| 🇷🇺 Русский | ✅ Основной (primary) | `shared/locales/ru.json` |
| 🇬🇧 Английский | 🚧 В процессе | `shared/locales/en.json` |

---

## Структура файлов

Переводы лежат в `shared/locales/` в формате JSON с плоскими ключами:

```
shared/
└── locales/
    ├── ru.json    # Русский — эталон
    └── en.json    # Английский
```

Пример структуры ключей:

```json
{
  "app.name": "Job Fit Copilot",
  "panel.title": "Разбор совпадения",
  "panel.analyze": "Проанализировать",
  "ats.score": "ATS-скор",
  "ats.hardRequirements": "Обязательные требования",
  "ats.niceToHave": "Желательные требования",
  "ats.gaps": "Критичные пробелы",
  "compare.title": "Сравнение резюме",
  "settings.apiKey": "API-ключ",
  "settings.provider": "Провайдер",
  "errors.noResume": "Сначала сохраните резюме в профиле"
}
```

## Как добавить новый язык

### Шаг 1. Создайте файл перевода

Скопируйте эталонный файл:

```bash
cp shared/locales/ru.json shared/locales/de.json
```

### Шаг 2. Переведите значения

Откройте новый файл и переведите все значения (то, что справа от `:`). **Ключи не меняйте** — по ним код ищет строки.

Правила:

- Ключи (`"panel.title"`) остаются на английском без изменений
- Значения переводятся на новый язык
- Плейсхолдеры вида `{name}`, `{count}`, `{score}` — не переводить и не удалять
- HTML-теги в строках (если есть) — сохранить как есть
- Технические термины (ATS, API, LLM, Fit-Check) обычно не переводятся

### Шаг 3. Зарегистрируйте язык

Добавьте язык в список поддерживаемых в настройках (см. массив `SUPPORTED_LOCALES` в `shared/` и секцию `default_locale` / локали в `manifest.json` при необходимости).

### Шаг 4. Проверьте полноту

Убедитесь, что в новом файле есть все ключи из `ru.json`:

```bash
node -e "
  const ru = require('./shared/locales/ru.json');
  const de = require('./shared/locales/de.json');
  const missing = Object.keys(ru).filter(k => !(k in de));
  console.log(missing.length ? 'Не хватает: ' + missing.join(', ') : 'OK: все ключи на месте');
"
```

### Шаг 5. Прогоните проверки

```bash
npm run check   # линт + тесты
```

### Шаг 6. Отправьте PR

См. [CONTRIBUTING.md](../CONTRIBUTING.md): форк → ветка `i18n/de` → коммит → PR. В описании PR укажите язык и, желательно, скриншот интерфейса на новом языке.

## Workflow переводов

1. **Эталон — русский.** Новые строки сначала появляются в `ru.json`.
2. **Английский — второй приоритет.** Обновляется следом за русским.
3. **Остальные языки** обновляются контрибьюторами по мере возможностей. Частичный перевод лучше, чем никакого — отсутствующие ключи автоматически показываются на английском (fallback).
4. **Изменения строк** фиксируются в CHANGELOG — следите за релизами, чтобы подтянуть новые ключи.

---

## Стиль и тон

- Обращение к пользователю — на «вы» (для русского) / формальный стиль для других языков
- Краткость: строки интерфейса — не место для длинных формулировок
- Кнопки — глаголы («Проанализировать», не «Анализ»)
- Числа и проценты — через плейсхолдеры, а не вшитые в строку
