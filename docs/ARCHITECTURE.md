# Архитектура Job Fit Copilot

Краткая карта системы для контрибьюторов. Подробности — в коде и тестах.

## Обзор

```
┌─────────────────────────── Chrome (MV3) ───────────────────────────┐
│                                                                    │
│  content-scripts/          sidepanel/ (SPA)          options/      │
│  парсинг вакансии  ──────▶  UI: разбор, профиль,     настройки,    │
│  с активной вкладки         сравнение, аналитика     API-ключи     │
│                                                                    │
│  background.js (service worker)                                    │
│  роутинг сообщений, direct LLM API calls                           │
└────────────────────────────┬───────────────────────────────────────┘
                             │ (опционально)
┌────────────────────────────▼───────────────────────────────────────┐
│  server/ (Node.js, 127.0.0.1)                                      │
│  index.js ─ HTTP: REST /api/* + MCP (mcp.js)                       │
│  db.js (SQLite) · bridge.js (hh.ru client) · sites/ (адаптеры)     │
│  core/ — бизнес-логика (см. ниже)                                  │
└────────────────────────────────────────────────────────────────────┘
```

## Ключевой принцип: детерминированный скоринг

Fit Score, ATS-оценка и ранжирование резюме считаются **формулой**
(`core/scoring.js`), а не LLM. LLM отвечает только за текстовый разбор и
генерацию. Это делает результаты воспроизводимыми и тестируемыми — вся
математика покрыта юнит-тестами (`test/`).

## Модули core/

| Модуль | Ответственность |
|--------|----------------|
| `scoring.js` | Fit Score, ATS-скор, ранжирование резюме. Чистые функции, без I/O |
| `fsm.js` | Воронка отклика: draft → analyzing → reviewed → approved → submitted → responded |
| `llm.js` | Единый клиент для NVIDIA NIM / OpenAI / Anthropic, retry + timeout |
| `prompts.js` | Все промпты. Промпты — код, версионированы вместе с кодом |
| `letter-lint.js` | Фильтр клише в сопроводительных письмах |
| `autopilot.js` | Пакетная обработка вакансий, human-in-the-loop: отправка только после явного одобрения |
| `resume-summary.js` | Сводка резюме, топ-роли, чек-лист правок |

## Приватность и границы

- Расширение читает **только активную вкладку** (`activeTab`).
- Отправка отклика работодателю возможна только после явного одобрения
  пользователя в панели — это инвариант FSM, а не договорённость.
- LLM-запросы идут напрямую к провайдеру с ключом пользователя; отдельного
  бэкенда у расширения нет.
- Сервер (если запущен) слушает только `127.0.0.1`.

## Общие константы

`shared/constants.js` — единственный источник истины для констант и
промптов, общих между расширением и сервером. Менять значения нужно там,
а не дублировать.

## Тесты

`node --test` без браузера: чистые функции core/ тестируются напрямую,
LLM-зависимости мокаются. CI (`.github/workflows/ci.yml`) гоняет линт и
тесты на каждый push/PR.
